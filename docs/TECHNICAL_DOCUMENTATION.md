# Technical Documentation

## 1. Architecture

The laboratory is a static, data-driven single-codebase site. Every HTML file is a thin shell generated by `tools/build.js`; the page type (`data-page`), its relative root (`data-root`) and its subject (`data-unit`, `data-topic`, `data-sim`, `data-exp`) are attributes on `<body>`. `js/app.js` renders the page from the data files, and `js/simulation-engine.js` mounts simulations.

```
config.js ─┐
vendor libs ─┤
equation-engine.js  (RIL.M: pure maths, also loadable in Node for tests)
simulation-engine.js (RIL.defineSim / RIL.mountSim, toolbar, controls, read-outs, charts, record/CSV, render loop)
three-kit.js        (RIL.three: scene factory, frames, DH robot renderer, picking, labels)
bundle-data.js      (00-course, 00-helpers, u1–u4, x-experiments, y-quiz)
bundle-sims.js      (00-common + u1-a … u4-d simulation definitions)
quiz-engine.js      (practice page only)
navigation.js → app.js (router: home, syllabus, unit, topic, sims, sim, exps, exp, practice, about)
```

Script order is fixed in the shell; there are no ES-module imports, so the site works from `file://` and from any sub-path.

### Library versions (bundled, `assets/vendor/`)
| Library | Version | Use |
|---|---|---|
| Three.js | r147 (UMD `three.min.js`) + `OrbitControls.js` from the same release | 3D scenes |
| Chart.js | 4.4.x UMD | real-time graphs |

## 2. Simulation API

```js
RIL.defineSim({
  id, title, unit, category, kind: '2d' | '3d' | 'html', description, help,
  controls: [{ id, label, min, max, step, value, unit } | { type: 'select'|'toggle'|'buttons'|'text', ... }],
  readouts: [{ id, label, unit, digits }], charts: [{ id, title, x, y, series, window, xType }], panels: [{ id, title, wide }],
  equations: ['TeX', ...],           // shown under the simulation
  auto, autoDefault, autostart, substeps, stepDt, stepFrames, camera,
  setup(S), reset(S), step(S, dt), draw(S), onControl(S, id, v), onButton(S, id), onPointer(S, type, x, y), onMode(S, auto)
});
```

`S` (the mounted instance) exposes `S.p` (parameters), `S.set(id, value)` (read-outs), `S.chart(id).push/set/clear`, `S.panel(id)`, `S.setParam`, `S.ctx` / `S.W` / `S.H` (2D canvas), `S.three` (3D scene kit), `S.t`, `S.running`, `S.auto`, `S.record()` and `S.downloadObs()`.

The global loop advances only visible simulations (IntersectionObserver), clamps frame time to [0, 50 ms], and integrates with `substeps` per frame. Stiff models run in scaled time (DC motor ×1/20, BLDC ×1/4) and say so on screen.

## 3. Equation engine (`js/equation-engine.js`)

Pure functions grouped as: vectors and matrices (inverse, determinant, damped least squares), rotations and homogeneous transforms (3.4–3.9), DH forward kinematics, geometric Jacobian (3.19), numerical IK (DLS), planar 2R kinematics/IK/Jacobian/dynamics/energy (3.11–3.31), trajectories (3.22–3.26), RK4, instrumentation (Unit I equations including type K reference table), actuators (2.1–2.23), signal conditioning and conversion (2.25–2.36), automation (4.1–4.17), image processing (convolution, median, Sobel, histogram, Otsu, threshold, blob moments, Harris corners), formatting and a seeded random generator. `tests/math.test.js` checks 129 values against the worked examples of the notes.

## 4. Content data model

```js
RIL.units.push({ n, roman, title, desc, syllabus, topics: [{
  id, n, title, refs, blurb, intro, objectives[], theory (HTML), principle (HTML), diagram (SVG), diagramCaption,
  model: [{ title, text, tex, vars: [[symbol, meaning, unit]] }], examples: [{ title, body }],
  sims: [simIds], simIntro, analysis, applications[], observations[], supplementary, questions: [{ q, a }], summary }] });
RIL.experiments.push({ unit, id, title, topics[], sim, aim, theory, setup, procedure[], observe, graphs, conclusion, questions[], preset{} });
RIL.quiz[unit] = [{ topic, cat, q, options[], answer } | { topic, cat: 'Numerical', type: 'num', q, answer, unit, tol }];
```

The topic page renders the 14-part template (introduction, objectives, theory, principle, diagram, model, simulation, results, applications, observations, supplementary, questions, summary) and omits empty parts. Experiments mount their simulation, apply `preset`, and copy every **Record** row into the observation table.

## 5. Build

`node tools/build.js` concatenates `js/data/*.js` and `js/sims/*.js` (alphabetical), loads them in a stub environment to read metadata, writes all page shells, `quizzes/*.json`, `docs/SYLLABUS_CONTENT_MAPPING.md`, `docs/SIMULATION_CATALOG.md` and `tests/pages.json`, and reports any topic without a simulation, missing simulation references or unused simulations (exit code 1 if any).

## 6. Tests

| Script | Purpose |
|---|---|
| `tests/math.test.js` | Engine against the notes' worked examples (Units I–IV). |
| `tests/smoke.js [filter]` | Loads every generated page in headless Chromium (SwiftShader WebGL) through a local server; fails on console errors, page errors, failed requests or render-failure callouts. On simulation and experiment pages it clicks Start/Pause/Step/Auto/Manual/Record/Reset, drives every slider to min/max/default, every select through all options, every toggle and every button, and fails on NaN read-outs. Writes `tests/smoke-report.json`. |
| `tests/functional.js <page> <s>` | Runs one simulation at 4× and prints its read-outs every 5 s (used to confirm that robot cells complete cycles, vision inspection classifies, AMR reaches its goal). |
| `tests/shot.js <page> <png>` | Screenshot helper. |

## 7. Accessibility and responsiveness

Semantic landmarks, skip link, labelled controls (each slider has a matching number input), `aria-pressed` toggles, keyboard-operable buttons, light/dark theme toggle for theory pages, `prefers-reduced-motion` respected on the home robot, layouts collapse to one column on phones; canvases redraw on resize; long equations scroll horizontally.

## 8. Extending

Add a simulation: create or edit a file in `js/sims/`, call `RIL.defineSim`, reference its id in a topic's `sims` array, run the build, then `node tests/smoke.js <id>`.
